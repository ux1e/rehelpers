# rehelpers

Небольшая header-only библиотека на C++17 с тремя независимыми модулями для
разбора и рантайм-инструментации бинарников. Написана как компактная витрина
техник, которые я использую в закрытом проекте (см. основной репозиторий
профиля) — здесь то же самое, но на нейтральном, полностью самодостаточном
примере, без привязки к какому-либо стороннему софту.

## Модули

**`pattern_scanner.hpp`** — сигнатурный поиск байтовых паттернов с wildcard
(в стиле IDA: `"48 8B 05 ?? ?? ?? ??"`). Применяется, чтобы находить адреса
функций/структур по устойчивой последовательности байт, когда явных символов
нет либо они сместились после пересборки/патча.

**`vtable_hook.hpp`** — RAII-обёртка для перехвата виртуального метода через
подмену записи в vtable объекта. Хук снимается автоматически в деструкторе
(unhook при выходе из области видимости). Под капотом — временное снятие
защиты страницы памяти (`mprotect` на Linux, `VirtualProtect` на Windows,
выбор через `#ifdef`).

**`pe_parser.hpp`** — read-only парсер формата PE: DOS/NT-заголовки, таблица
секций, конвертация RVA → file offset, список импортируемых DLL. Работает
над обычным байтовым буфером — платформенно независим, ничего не грузит и не
исполняет.

## Демонстрация

`examples/demo.cpp` прогоняет все три модуля подряд:

```
== pattern_scanner ==
  сигнатура найдена по смещению 4

== vtable_hook ==
  оригинальный greet()
  [hook] перехвачен вызов greet()
  оригинальный greet()

== pe_parser (sample.exe) ==
  архитектура:     PE32+ (x64)
  entry point RVA: 0x1410
  image base:      0x140000000
  секции (19):
    .text     VA=0x00001000  VSize=0x006b68  RawSize=0x006c00  R-X
    ...
  импортируемые DLL (2):
    KERNEL32.dll
    msvcrt.dll
```

`examples/sample.exe` — маленький PE32+ бинарник, собранный mingw-w64,
специально для того, чтобы демо парсера можно было запустить сразу, без
поиска стороннего .exe/.dll под рукой.

`Greeter` в демо намеренно вынесен в отдельную единицу трансляции
(`greeter.hpp` / `greeter.cpp`) — иначе компилятор на `-O2` девиртуализирует
вызов `g->greet()` (подставит прямой адрес функции вместо обращения через
vtable), и хук окажется незаметен в рантайме. В реальности хукается код,
которого у тебя нет в той же единице трансляции, так что это разделение
заодно честнее показывает суть техники.

## Сборка

Проект — под MSVC (Visual Studio 2022, toolset v143, C++17), конфигурации
Debug/Release на x64:

1. Открыть `rehelpers.sln` в Visual Studio.
2. Если студия предложит "Retarget solution" (не совпадает установленный
   Windows SDK) — согласиться, это нормально и занимает один клик.
3. Собрать (Ctrl+Shift+B) и запустить `demo` (F5 / Ctrl+F5).

Working directory для отладки уже настроен на `examples\`, так что демо
сразу найдёт `sample.exe` без дополнительных аргументов.

В Release-конфигурации намеренно выключена Whole Program Optimization
(LTCG) — иначе линковщик на этапе LTCG может девиртуализировать вызов
`g->greet()` через границу `demo.obj`/`greeter.obj`, и хук окажется не
виден в релизной сборке (та же причина, по которой `Greeter` вынесен в
отдельную единицу трансляции — см. ниже).

Библиотека сама по себе — три independent header-файла без зависимостей,
их можно просто скопировать в любой другой MSVC/CMake/что угодно проект и
подключить `#include "rehelpers/..."` — сборочная система вокруг демо нужна
только для самого демо-приложения.


## Ограничения (сознательно, чтобы не разрастаться за пределы демо)

- `vtable_hook` рассчитан на простое одиночное наследование (Itanium ABI и
  MSVC ABI в этом случае кладут индекс 0 = первый объявленный виртуальный
  метод); множественное наследование не обрабатывается.
- Запись в vtable не обрабатывает случай, когда изменяемый указатель
  оказывается на границе двух страниц памяти.
- Хук не потокобезопасен: если объект вызывается из нескольких потоков
  параллельно с установкой/снятием хука, нужна дополнительная синхронизация
  — здесь её нет.
- `pe_parser` разбирает заголовки, секции и таблицу импорта; таблицы
  экспорта, релокаций и ресурсов не реализованы — при необходимости
  дописываются по той же схеме (RVA → offset уже есть).

## Стек

C++17, CMake ≥ 3.15. Внешних зависимостей нет.
